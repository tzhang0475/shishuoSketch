# SFH2.2-F-prep — Production Architecture Freeze

SFH2.2-F-prep closes the offline SFH2.2 pilot phase and freezes a
candidate-only production architecture. It does not run a provider, rebuild
the full corpus, write a Person, or promote semantic output to canonical
authority.

## Qualified semantic architecture

The qualified architecture is recorded in
`data/frozen/sfh2/semantic-v1/` and is derived from the A2R/A2GR, A2OR, and
A2OVB experiments:

* identity uses the frozen A2R/A2GR dual-historian, structural-comparison, and
  adjudication contract;
* provenance is structural: the target's exact `source_evidence_id` selects
  `source_evidence.source_layer`;
* A2OR is the qualified multiclass occurrence-function historian;
* A2OVB is the qualified primary-blind binary validator for only primary
  `participant`/`reference` results;
* the old `occurrence_role` is only a generic compatibility projection;
* the A2OV primary-aware reviewer is explicitly excluded. Its 26-confirm,
  zero-revision pilot was a negative incremental-value experiment;
* all output is a candidate semantic record. Human review is the promotion
  boundary, and canonical write-back remains false.

The production DAG is therefore:

```text
exact occurrence
  -> structural provenance
  -> qualified frozen identity
  -> A2OR multiclass function
       -> A2OVB only for participant/reference (primary-blind packet)
  -> final narrative_function
  -> generic legacy-role projection
  -> candidate record
  -> human review / explicit promotion
```

Neither Python nor retrieval may infer historical identity or semantic role
from a Chinese surface. Python validates structure, applies declared
mechanical mappings, and enforces storage safety.

The A2OVB pilot achieved 26/26 on its reviewed pilot. That qualifies the
architecture and task decomposition; it is not a claim that unseen full-corpus
production will be 100% accurate.

## Derived scope and exact occurrences

The scope is derived from the current SFH1 reading-packet registry, with the
UX2 index recorded as the published-runtime cross-check. The result is 188
eligible Stories: 143 in the published runtime scope and 45 research-only
Stories. The historical “188-Story” scope is therefore confirmed by current
authority rather than hard-coded.

The authoritative mention ledger contains 3,303 validated occurrences: 1,282
from `main_text` and 2,021 from `liu_annotation`. Every target is pinned by
the occurrence ID, mention ID, Story, evidence ID, exact offsets, and surface.
The preflight found no dangling evidence, offset/text mismatch, or duplicate
exact key. It records 264 overlap/nested span pairs and 308 repeated
Story/surface groups explicitly; these are not silently collapsed.

## Identity readiness

Of the 3,303 occurrences, 26 have an exact reusable qualified pilot identity
context, 2,842 require the frozen identity pipeline, and 435 are explicitly
validated non-person/collective occurrences for which identity resolution is
not applicable. No occurrence is structurally blocked. A new historical Person
can only be proposed as a candidate through the qualified identity pipeline;
it can never be automatically created in canonical data.

## Review, cache, and recovery rules

Review routing is based only on structured pipeline state: identity abstention
or unresolved adjudication, new Person candidates, invalid contracts, exact
evidence failures, uncertain occurrence/boundary output, provider failure,
unsupported projection, and declared stage disagreement. Low confidence and
boundary overrides are audit flags, not automatic semantic authority.

Provider results are reusable only when stage, prompt/schema, model and
configuration, exact packet, exact occurrence key, source hashes, frozen
identity input, and `request_hash` all match. The audit identifies 41 exact
pilot result candidates (26 A2OR and 15 A2OVB); reuse still requires equality
with the request hash generated by the future production packet.

Stable checkpoint units are `identity:<occurrence_key>`,
`occurrence_primary:<occurrence_key>`, and
`boundary:<occurrence_key>`. A valid matching request hash may resume a unit;
a changed hash is never silently reused. Contract-invalid output is not
coerced. HTTP 400 is non-retryable; a transient 429/5xx/timeout/connection
reset may receive at most one retry and then becomes review-blocked.

Raw provider envelopes are external-archive-default under C3. F-prep writes
only compact scope, cache, checkpoint, policy, and metric artifacts.

## Budget and first wave

The planning artifacts contain low/minimum, pilot-observed, and worst-case
estimates. With 2,842 identity-pipeline units, 3,277 new A2OR occurrence calls,
and 41 exact pilot cache candidates, total estimated new calls are 8,964 at
minimum, 13,200 at the observed pilot rates, and 15,083 at worst case. The
boundary estimate is 0 / 1,891 / 3,277 for minimum / pilot / worst case on the
new occurrence calls. Token and storage estimates are calculated from
observed qualified-stage usage; no currency price is invented.

F1 is a deterministic, risk-stratified selection of 30 occurrences across 25
Stories. It includes source-layer, entity/reference-form, identity-readiness,
overlap/repetition, and participant/reference-boundary risk strata. It is
recorded in `f1-selection.json` and is explicitly not executed in F-prep.
Its pilot-observed estimate is 121 provider calls, including three contract
probes. Gold is not used to select ordinary F1 targets.

Before F1, abort on any canonical write, production Person creation,
protected-hash mutation, Gold leakage, invalid exact key, provenance failure,
identity mutation outside the declared identity stage, boundary packet primary
leakage, copy drift, or undeclared mutation. Stop for pre-frozen contract,
checkpoint, request-hash, provider-failure, or C3-growth violations.

## Boundaries

F-prep does not start F1, does not claim full-corpus accuracy, and does not
modify SC1/WP1, canonical data, Gold, reviewed annotations, or historical
pilot outputs. The next stage, if the offline validator and current test
contract pass, is `SFH2.2-F1`.
