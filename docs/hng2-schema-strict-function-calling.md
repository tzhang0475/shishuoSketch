# HNG2-SC strict Function Calling

HNG2-SC semantic EvidenceCards use DeepSeek's Beta strict Function Calling
interface.  The transport base is `https://api.deepseek.com/beta`, and the
raw HTTP completion path is `/chat/completions` below that base.  The runner
forces the single function `submit_historical_entity_card` and does not send
`response_format=json_object` for semantic calls.

The function parameters are generated by
`scripts/hng2_schema_strict_tools.py` from the controlled values in
`historical_entity_schema.py`.  Every object property is required and every
object rejects additional properties.  Because strict mode requires required
object properties, nullable Python strings use an empty-string wire sentinel;
the deterministic adapter converts that sentinel back to the existing
controller representation before `validate_card_payload` runs.  This is a
transport conversion, not semantic repair.

The semantic system prompt describes the historical task only.  Field names,
enum values, and descriptions live in the function schema.  The controller
reads only `choices[0].message.tool_calls[0].function.arguments`, requires the
exact function name, and then applies the existing provenance, candidate,
identity, graph-safety, and canonical-write validators.

Run the offline replay first:

```text
python3 scripts/run_hng2_schema_controller_strict.py --mode replay
python3 scripts/validate_hng2_schema_controller_strict.py --mode replay
```

The live command is deliberately separate and must start in an approved
network execution:

```text
python3 scripts/run_hng2_schema_controller_strict.py --mode live \
  --run-id <new-run-id>
python3 scripts/validate_hng2_schema_controller_strict.py --mode live
```

Results are isolated under
`data/generated/hng2-schema-controller-strict/`; prior SC.1 JSON-mode raw
responses are not overwritten.
